\chapter{Background and Related Work}

\section{Biomedical Information Retrieval}

Biomedical information retrieval provides the evidence-access layer on which this thesis builds. Its purpose is to identify literature that can support a biomedical question while preserving enough provenance for later inspection. PubMed and the wider Entrez ecosystem provide a programmatic route into biomedical bibliographic data through the National Center for Biotechnology Information (NCBI) E-utilities, which support search and retrieval over databases including PubMed \cite{sayers2022eutilities}. This matters for the present thesis because the implemented scheduler service and ingestion workflow depend on stable literature identifiers, especially Digital Object Identifiers (DOIs) and PubMed Identifiers (PMIDs), rather than treating documents as anonymous text fragments.

% evidence: biomed_knowledge_platform/src/biomed_platform/core/use_cases/document_fetch.py

Classical biomedical search is not a weak baseline. PubMed Best Match demonstrates that production biomedical retrieval can combine lexical candidate generation with learned reranking: its architecture first retrieves using BM25-style term weighting and then reranks candidates using LambdaMART learning-to-rank features \cite{fiorini2018bestmatch}. This design is important because it separates candidate recall from final ranking quality. A RAG system that relies on dense vector retrieval makes a different representation choice, but it faces the same operational requirement: retrieve a sufficiently broad candidate pool, rank evidence effectively, and expose the top-ranked content under bounded latency and context-size constraints.

Biomedical information retrieval also has a long benchmark tradition. BioASQ framed large-scale biomedical semantic indexing and question answering as a combined retrieval and synthesis problem over biomedical literature, with expert-created questions, retrieved snippets, and ideal answers \cite{tsatsaronis2015bioasq}. The TREC Precision Medicine Track similarly emphasized retrieval for clinically structured cases, where evidence ranking must account for disease, gene, variant, and treatment relevance rather than superficial textual overlap \cite{roberts2020trecpm}. These benchmark traditions justify evaluating retrieval as its own stage. If relevant evidence is absent from the retrieved context, no downstream generator can reliably recover the missing source.

Recent biomedical retrieval work has moved beyond purely lexical matching. MedCPT trains contrastive biomedical retrievers and rerankers from large-scale PubMed search logs, showing that user-query and click behavior can support zero-shot biomedical information retrieval \cite{jin2023medcpt}. BioBERT and related biomedical language models further demonstrate that domain-specific pretraining improves biomedical text understanding compared with general-domain language representations \cite{lee2020biobert}. Sentence-transformer architectures provide the general dense embedding basis for semantic similarity search \cite{reimers2019sentencebert}. These lines of work support the design choice in this repository to index biomedical text as embedded chunks in a vector database, while also making clear that the chosen embedding model, chunking policy, and ranking procedure are empirical design variables rather than neutral implementation details.

% evidence: biomed_knowledge_platform/src/biomed_platform/core/services/ingestion/chunking.py
% evidence: biomed_knowledge_platform/src/biomed_platform/adapters/qdrant/vector_index.py

For this thesis, the practical implication is that biomedical information retrieval must preserve three properties at the same time: semantic recall, provenance, and controlled ranking depth. PubMed-derived identifiers provide provenance; chunk-level indexing provides retrievability; and top-k limits prevent unbounded prompt growth. The literature therefore motivates a retrieval layer that is explicit enough to evaluate independently and structured enough to support answer-level citation.

\section{Retrieval-Augmented Generation}

Retrieval-Augmented Generation (RAG) couples a parametric language model with retrieved non-parametric evidence at inference time. Lewis et al. introduced this paradigm for knowledge-intensive natural language processing tasks, arguing that retrieved passages can improve factual specificity and provide an updateable memory external to the model parameters \cite{lewis2020rag}. This distinction is central for biomedical work. Biomedical knowledge changes continuously, and relying only on a model's parametric memory would make the system dependent on opaque training data and a fixed knowledge cutoff.

In a biomedical setting, RAG is best understood as an evidence-conditioning architecture rather than as a guarantee of clinical correctness. The retrieval stage selects candidate evidence from the indexed corpus (the searchable collection of embedded document chunks); the synthesis stage generates an answer conditioned on the selected context; and citation handling links answer content back to retrieved sources. The implemented biomedical RAG service follows this pattern by separating ingestion, retrieval, and answer synthesis into distinct use cases. The architecture therefore aligns with the literature's core motivation for RAG: explicit access to external evidence and clearer provenance than closed-book generation.
% evidence: biomed_knowledge_platform/src/biomed_platform/core/use_cases/search.py
% evidence: biomed_knowledge_platform/src/biomed_platform/core/use_cases/ask.py

Several medical RAG systems illustrate the same direction. Clinfo.ai uses scientific literature retrieval to answer medical questions and explicitly evaluates retrieval and synthesis behavior \cite{lozano2024clinfo}. Almanac applies retrieval-augmented language modeling to clinical medicine and includes physician evaluation over clinical scenarios \cite{zakka2024almanac}. Benchmarking Retrieval-Augmented Generation for Medicine introduces MIRAGE and the MedRAG toolkit to compare corpora, retrievers, and models across medical question answering datasets \cite{xiong2024benchmarking}. These systems support the thesis position that biomedical RAG should be evaluated as a pipeline of interacting components, not only as a generated-answer interface.

The literature also motivates configurable retrieval expansion. Hypothetical Document Embeddings (HyDE) generate a synthetic answer-like passage from the query and embed that generated text to retrieve semantically related documents without requiring relevance labels \cite{gao2023hyde}. This is relevant to the repository because HyDE is implemented as an optional retrieval mode. Its expected benefit is improved recall for underspecified questions; its risk is expansion noise when the original biomedical query is already precise. This tradeoff appears in the thesis evaluation, where no-HyDE and HyDE configurations are compared rather than treating HyDE as a universally beneficial enhancement.

\section{Biomedical RAG Challenges}

Biomedical RAG inherits the difficulties of biomedical information retrieval and adds generation-specific risks. The first challenge is terminology. Biomedical questions often mix clinical language, mechanistic terminology, abbreviations, disease names, procedures, and outcome measures. A thrombosis-oriented question may refer to venous thromboembolism, deep vein thrombosis, pulmonary embolism, catheter failure, anticoagulation, or postoperative risk using different textual forms. Dense retrieval can reduce exact-term dependence, but it can also retrieve semantically nearby yet clinically misaligned evidence. This makes provenance-bearing metadata and post-retrieval evaluation essential.

The second challenge is freshness. PubMed-based systems operate over a literature stream that changes continuously. Static corpora are easier to reproduce, but they become stale; continuously updated corpora are more current, but they require identifier tracking, deduplication, and run-level traceability. The scheduler service in this repository addresses this by separating acquisition from answer generation and by using DOI and PMID workflows to make ingestion outcomes inspectable. The literature on RAG in healthcare identifies up-to-date external evidence as one of the main motivations for RAG, while also emphasizing that healthcare RAG still lacks standardized evaluation and governance practices \cite{amugongo2025healthcarerag}.

% evidence: scheduler_pubmed/src/adapters/rag/documents_client.py

The third challenge is grounding. A generated answer can be fluent, relevant, and still unsupported by the retrieved sources. Conversely, a response can be faithful to retrieved context that is incomplete, outdated, or not clinically authoritative. This distinction is especially important in medicine. Evaluations of medical RAG systems show improvements from retrieval in some clinical tasks, including anticoagulation-management questions, but also conclude that RAG-supported outputs remain insufficient for autonomous clinical use \cite{malik2024anticoagulationrag}. Therefore, the thesis treats RAG outputs as evidence-grounded information artifacts, not as diagnostic or treatment recommendations.

The fourth challenge is corpus granularity. Biomedical articles contain titles, abstracts, methods, results, discussion sections, and bibliographic metadata. Retrieval over entire documents can hide relevant passages; retrieval over very small fragments can lose context. The implemented system uses chunked indexing with preserved metadata so that retrieval can operate at chunk level while answers retain article-level provenance. This design follows the broader movement toward passage- and snippet-level biomedical retrieval seen in BioASQ and related systems, while keeping the implementation bounded enough for MSc-level evaluation.

\section{Evaluation of RAG Systems}

RAG evaluation must be decomposed because retrieval failure, grounding failure, and task-output failure are different phenomena. Retrieval metrics such as normalized discounted cumulative gain, precision at k, recall at k, and mean reciprocal rank measure whether relevant sources are ranked highly enough to enter the answer context. Normalized discounted cumulative gain is particularly appropriate when relevance is graded because it rewards ranking more useful evidence earlier \cite{jarvelin2002ndcg}. BEIR reinforces the need to test retrieval systems across heterogeneous tasks rather than relying on a single narrow benchmark \cite{thakur2021beir}. In the biomedical domain, BioASQ and PubMedQA further show that biomedical question answering requires evidence selection and answer evaluation over biomedical abstracts and expert-derived labels \cite{tsatsaronis2015bioasq,jin2019pubmedqa}.

Answer-level evaluation adds a separate layer. RAGAS proposes reference-free metrics for RAG pipelines, including faithfulness, answer relevancy, and context precision \cite{es2024ragas}. These metrics match the evaluation subsystem in this repository: answer relevancy assesses whether the response addresses the question, faithfulness estimates whether answer claims are supported by retrieved contexts, and context precision estimates whether retrieved contexts are useful for the answer. However, these metrics should not be interpreted as biomedical truth verification. They diagnose grounding behavior relative to supplied context.
% evidence: evaluation_metrics/src/phases/phase4_ragas.py

Other RAG evaluation frameworks support this decomposition. ARES evaluates context relevance, answer faithfulness, and answer relevance using synthetic data and smaller human-labeled validation sets \cite{saadfalcon2024ares}. RAGChecker argues for fine-grained diagnosis of retrieval and generation modules instead of a single aggregate RAG score \cite{ru2024ragchecker}. These frameworks support the phase-based evaluation design used in this thesis, where answer generation is materialized before scoring and where retrieval, RAGAS, audit, and extraction phases can be inspected separately.

For thrombosis-oriented questions, task-specific extraction metrics are also needed. A response may be grounded and relevant but still miss a risk factor or add one unsupported by the reference set. The evaluation subsystem therefore includes risk-factor extraction analysis with precision, recall, and F1 over a closed canonical vocabulary. This aligns with biomedical NLP practice, where extraction tasks are usually evaluated against curated labels rather than only against free-form textual impressions.

\section{Human Validation Workflows}

Human validation is a methodological requirement in biomedical NLP because gold-standard labels are rarely self-evident. Deleger et al. describe gold-standard corpus construction for medical NLP using double annotation, consensus, and inter-annotator agreement measurement \cite{deleger2012goldcorpora}. Risk-factor extraction work in the i2b2/UTHealth shared task operationalized clinically meaningful labels such as diabetes, coronary artery disease, hypertension, hyperlipidemia, obesity, smoking, and family history, showing how explicit annotation schemas support reproducible extraction evaluation \cite{stubbs2015i2b2risk}. Stubbs and Uzuner further demonstrate risk-factor annotation with medically trained annotators and majority-vote gold standards \cite{stubbs2015riskannotation}.

Human-in-the-loop workflows can also improve annotation efficiency without removing human responsibility. Neveol et al. found that semi-automatic semantic annotation of PubMed queries reduced manual effort while preserving or improving annotation quality \cite{neveol2011semiannotation}. This motivates a pragmatic thesis workflow: software can prepare candidate tasks, normalize metadata, and structure exports, while human review remains responsible for judging label meaning and evidence adequacy.

The repository uses Label Studio as a curation surface, with supporting tools that transform biomedical abstract collections into review tasks and export reviewed annotations for downstream processing. Label Studio is general-purpose labeling software rather than biomedical validation evidence \cite{tkachenko2020labelstudio}; its value here is operational. It provides a traceable interface for human review, while repository tooling preserves DOI, PMID, title, abstract, and annotation fields for evaluation. The current thesis therefore treats curated labels as a reproducible reference substrate, not as a fully adjudicated clinical gold standard.
% evidence: evaluation_metrics/src/phases/phase6_extraction.py

This boundary is important. Human validation in the thesis supports literature curation and evaluation of risk-factor extraction behavior. It does not establish prospective clinical safety, clinician workflow benefit, or treatment validity. Those claims would require a different study design, domain-expert adjudication protocol, and clinical evaluation setting.

\section{Local LLM Deployment Considerations}

Local LLM deployment is relevant to biomedical RAG for privacy, reproducibility, and operational control. Healthcare studies have explored local or privacy-preserving LLM pipelines for clinical text review and information retrieval. Vaid et al. used a local open-source LLM with retrieval over historic echocardiogram reports, showing that local deployment can support clinician-facing retrieval tasks while still producing errors that require validation \cite{vaid2024local}. Wiest et al. similarly evaluated privacy-preserving LLM use for structured medical information retrieval, demonstrating the feasibility of local clinical text extraction while comparing model outputs against expert-derived references \cite{wiest2024privacyllm}.

Local deployment does not by itself make a system safe. Reviews of LLMs in medicine emphasize hallucination, bias, validation, and governance risks \cite{thirunavukarasu2023llmmedicine}. Open medical LLM deployment also requires transparent model provenance, version control, and auditable update processes \cite{riedemann2024openmedicine}. This is directly relevant to the repository's use of a locally served Llama 3.1 8B model through Ollama. The model choice supports offline experimentation and avoids sending prompts to an external model provider, but it also constrains generation quality, hardware behavior, and reproducibility.
% evidence: biomed_knowledge_platform/configs/llm.yaml
% evidence: llm_server/docker-compose.yml

The reproducibility boundary for local LLMs is therefore broader than the model name. A reproducible run should record the model family, model tag or digest, quantization, context length, temperature, seed where supported, prompt template, embedding model, vector index state, and corpus snapshot. The Llama 3 model report describes the model family and release context \cite{dubey2024llama3}; however, a local quantized runtime is still a specific deployment artifact. In addition, local execution reduces third-party data transfer but does not eliminate privacy risk: language models can memorize and emit training data under some conditions \cite{carlini2021extracting}. For this thesis, the appropriate claim is therefore conservative: local deployment improves control and auditability for research evaluation, but it is not a substitute for governance, access control, or clinical validation.

\section{Research Gaps and Thesis Positioning}

The reviewed literature establishes mature foundations for biomedical retrieval, RAG, biomedical QA evaluation, annotation workflows, and local LLM deployment. The gap addressed by this thesis is not the invention of a new biomedical language model or a new clinical benchmark. Instead, the thesis targets the integration problem: how to combine continuous PubMed-oriented acquisition, chunked vector indexing, evidence-grounded synthesis, human curation, and reproducible evaluation in one repository-grounded research artifact.

Existing biomedical IR benchmarks motivate rigorous retrieval evaluation, but they do not by themselves define an operational ingestion architecture. Medical RAG systems demonstrate the value of retrieved evidence, but they often differ in corpora, retrievers, models, and evaluation protocols, making direct comparison difficult. RAG evaluation frameworks provide useful grounding diagnostics, but they do not verify biomedical correctness. Human validation workflows create more credible reference data, but they require explicit schema design and annotation governance. Local LLM deployment improves control, but it introduces model-version and resource constraints.

This thesis is positioned at the intersection of these gaps. Its contribution is an evidence-aware biomedical RAG platform and evaluation workflow for thrombosis-oriented literature questions. The platform is intentionally modular: the biomedical RAG service owns ingestion, retrieval, and synthesis; the scheduler service owns continuous literature acquisition; the evaluation subsystem owns phase-based measurement; and the Label Studio workflow supports curated reference artifacts. This positioning keeps the thesis claims defensible. The work evaluates a concrete system configuration under documented constraints, rather than claiming general clinical validity or universal superiority over other biomedical RAG architectures.
